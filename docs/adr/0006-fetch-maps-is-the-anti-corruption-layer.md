# fetch_maps is the anti-corruption layer: one validator, fail loud on contract drift

`fetch_maps` (`tarkov-map-fetch`, lib + bin per ADR-0004) is the only code that knows tarkov.dev's shapes — `maps.json` from the tarkov-dev repo (projection, labels, `altMaps`, attribution), `json.tarkov.dev/regular/maps` (spawns, extracts, the overlay collections) and `maps_en` (translations). Every upstream shape is a fetch-private DTO; the tool converts them into core's domain `Map` values as plain struct literals (pub fields — `ron` deserialisation bypasses constructors anyway), bakes the Projection (ADR-0003), applies the fixed display-order table, and writes the **Bundle** (`assets/maps.ron` + `assets/maps/*.bc7z`). We decided that **core holds the one set of invariants** — `MapCatalog::try_new(Vec<Map>) -> Result<MapCatalog, CatalogError>` — which fetch runs before it writes anything and adapters run after they load the bundled file, so there is no second validation language in fetch; fetch's own checks are about upstream shape only. And we fixed a failure taxonomy for a **Refresh**: a missing *value* on an entry (no position, < 3 outline vertices, no translation) is dropped with a warning; an unknown *variant* where the domain has an enum (an extract faction outside `pmc`/`scav`/`shared`, a hazard type outside `sniper`/`minefield`/`hazard`, an unparsable rotation) **fails the run**, because it is a contract change the domain must learn about, not noise; a required field missing on a Map we ship (one named in the order table) is **fatal** — exit non-zero, nothing written — because a release must not silently lose Customs; a group not in the table that is incomplete is skipped with a warning; and a complete new upstream Map is included automatically, appended after the table alphabetically, with a loud "add it to the order table" warning.

## Consequences

- **Required upstream fields** per Map: group `normalizedName`, an `interactive` projection entry, a display `name`, `bounds`, `coordinateRotation`, and either `svgPath` or (`tilePath` + `tileSize` + `transform` + `maxZoom`). `svgBounds`, `labels`, `author`/`authorLink` and every per-Map collection are optional (`None`/empty). By construction this fixes today's gaps: `svgBounds` is read (Reserve), and `image_size` is the rendered/stitched pixel size rather than a tile's.
- **One merge rule.** Every per-Map collection (`spawns`, `extracts` and the sibling map's six overlay collections) is the union over the canonical upstream entry and its `altMaps` entries, deduplicated by rounded position plus the entry's identity (faction/name/target); labels are canonical-only because only the canonical `maps.json` entry carries them. Coordinates are rounded to 2 decimals before dedup and before writing.
- **`MapImageKey` is the verbatim asset-relative path** (`maps/customs.bc7z`) as embedded by adapters: fetch decides it, adapters look it up as-is and never rebuild it, and the bundle-integrity check (every key exists, no orphan `.bc7z`) is a set comparison.
- **Writes are atomic and last.** `.bc7z` files and `maps.ron` are written to a temporary name and renamed only after `MapCatalog::try_new` accepts the converted set; a failed Refresh leaves the committed Bundle untouched. PNG intermediates stay as a gitignored cache under `assets/maps/`; images are regenerated only when missing or with `--force`, `maps.ron` always; `--tile-zoom-offset` (default 2), the 2× SVG render scale and `--convert-only` (re-encode cached PNGs when the bc7z format changes) are kept. Staging and provenance flags belong to the refresh-provenance work, not here.
- **Module shape** of the lib: `upstream` (DTOs + `fetch_all(client) -> Upstream`), `convert` (pure `convert(Upstream, &OrderTable) -> Conversion { maps, warnings, images_needed }` incl. `bake_projection`; unit-tested against `crates/core/testdata/projection-oracle.ron`), `images` (SVG/tile → PNG; BC7 → bc7z behind `encode`), `bundle` (`MapCatalog::try_new` + atomic write). Modules are `pub` for the bin and tests only (`publish = false`, no stability promise). `main.rs` is `Args` + `run(args)`.
- **Errors** follow ADR-0001: eros with `context` + `backtrace`; per-entry issues are collected warnings printed as a summary with counts; HTTP/IO failures are fatal unless they hit a non-table group. Exit code is non-zero iff the run is fatal.
- `CatalogError` diagnostics name the Map, collection and entry (index or name) and the failed invariant, since both the Refresh and the app's startup surface them.

## Considered options

- Drop-with-warning for unknown enum variants, like positionless entries — rejected: it would ship a Bundle quietly missing every extract of a new faction; failing makes the upstream change visible at refresh time, when a human is already looking.
- Skip-with-warning for shipped Maps with a missing required field (today's behaviour) — rejected for the same reason at Map granularity; `fetch_maps` knowing the order table makes "a Map we ship" cheap to define.
- A validation layer inside fetch mirroring core's rules — rejected: two rule sets drift; `MapCatalog::try_new` is already the load-time gate, so running it pre-write costs nothing.
- `MapImageKey` as a bare stem formatted by adapters, or the `MapId` itself — rejected: the key exists so that adapters never reconstruct paths; a verbatim path keeps that true and keeps the integrity check trivial.
- Canonical-only collections (today's behaviour) — rejected once the sibling map chose union for its six collections; one rule for every collection is simpler than two.
