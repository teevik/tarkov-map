# Sync model, effects out, async confined to one Effect Runner

The core's application model is a synchronous state machine — `Model::handle(&mut self, Message, now: SystemTime) -> Vec<Effect>` — that never awaits, spawns, holds a runtime handle, or calls a port. Everything slow or side-effecting leaves the model as an `Effect` value and comes back as a `Message`; exactly one component, the **Effect Runner** (in core, tokio allowed), matches on `Effect`s, runs them against the driven ports, and posts the resulting `Message`s back on one channel. This is the shape every canonical source uses for a long-lived owner of state — Alice Ryhl's actor (`handle_message` sync, only the receive loop async), Firezone's sans-IO machines, iced's `update -> Task` — and it is what the app already did informally with three separate `std::mpsc` + `thread::spawn` + `try_recv` loops. Async is the right sugar for *sequential* flows (check release → download → install; await the next screenshot event), so it lives inside the runner and the adapters, not in the reactive model.

## Vocabulary

- **Message** (`Msg` in code): anything that changes the model — a UI intent or the result of an Effect. `handle` is the model's *only* mutation path; the view is `fn(&Model, ui) -> Vec<Msg>`.
- **Effect**: a description of work the model asks for and never performs (decode this map's image, start watching this folder, check for an update). Every side effect the app can perform is a variant of one enum, so none can be added ad hoc.
- **Effect Runner** (`Runner` in code; avoid "executor", which is tokio's word): the single component that turns Effects into tasks over the ports and Messages back. Generic over one `Ports` bundle trait (`type Decoder: ImageDecoder; …` + accessors); the real bundle in the app, one `FakePorts` in tests.

## Consequences

- **Ports are sync where the work is sync.** `ImageDecoder::decode` (CPU) and `ReleaseFeed::latest/install` (`self_update` is `reqwest::blocking`) are plain fns; the runner calls `spawn_blocking`. Only event-driven ports are async: `PositionSource::observe(dir) -> impl Stream<Item = PositionEvent> + Send`. Native `async fn` in traits stays available if an adapter is ever genuinely async; no `async-trait`/`dynosaur`.
- **The model reads no ports.** The bundled map list is plain data given to `Model::new` (its failure is fatal, ADR-0001), so there is no `MapCatalog` port; time enters as a `now` value on `handle` and on queries such as `freshness(now)`, so the model needs no `Clock` port either (`Clock` remains a trait only if an adapter wants it). Fixed 120 s freshness threshold and similar rules are core constants.
- **No tick, no runner timers.** Time-dependent display (the Live→Stale flip) is a query; the view calls `request_repaint_after` for the next change. A timer, if ever needed, becomes an `Effect::After(dur, Msg)`.
- **Message path.** One `tokio::sync::mpsc::unbounded_channel::<Msg>()`; the runner calls a `wake: Arc<dyn Fn() + Send + Sync>` after each send (the app binds `ctx.request_repaint()`, keeping core egui-free); the app drains `rx.try_recv()` in `App::logic()` and dispatches: `for e in model.handle(msg, now) { runner.run(e) }`.
- **Cancellation is by named slot, not task id.** The runner holds one `CancellationToken` per long-lived job — `decode: Option<(MapName, token)>`, `watch: Option<token>`. `Effect::DecodeImage{map}` implicitly cancels the previous decode (at most one in flight); `Effect::WatchScreenshots(dir)` / `StopWatching` are explicit. Because `spawn_blocking` cannot be aborted once running, the model also drops `ImageDecoded{map}` for a map that is not selected — a tested branch. All tasks live in a `JoinSet` and are aborted on drop.
- **Runtime ownership.** The app crate's `main` builds `Runtime::new_multi_thread().worker_threads(2).enable_all()`, holds `rt.enter()`, gives the runner a `Handle`, runs `eframe::run_native`, then `rt.shutdown_timeout(2s)`. A headless binary is the same `Model` + runner under `block_on` with `wake = || {}`.
- **The app may intercept egui-bound effects** (exit to install an update, GPU upload) before delegating the rest to the runner: `match effect { Effect::Exit => …, other => runner.run(other) }`. Which such effects exist is decided with the updater/settings/notifications wiring; the set stays small.
- **Tests.** Model: plain `#[test]`, feed Messages, assert state and returned Effects by value — no runtime. Runner: `#[tokio::test]` (current-thread) with `FakePorts`, assert Messages received; cancellation via a fake decoder that blocks on a `Notify`.

## Considered options

- **Async model** (`async fn handle`, awaits inside) — rejected: it either freezes the frame loop or moves the model off the UI thread, and immediate-mode egui needs `&Model` every frame; Firezone's sans-IO argument (spawned futures need `'static`, pushing you to `Arc<Mutex<_>>`) applies directly.
- **iced-style `handle(msg, ports) -> Vec<Task<Msg>>`** (model builds boxed futures from ports; runner is a dumb spawner) — rejected: less boilerplate but the model then holds ports, model tests need a runtime to see what a task does, and cancellation needs handles threaded through tasks. Effects-as-values keep the full side-effect surface visible in one enum.
- **`Arc<Mutex<Model>>` mutated from tasks** — rejected: Rust for Rustaceans ch. 10 — a single owner handling messages needs no locks; and there is no non-commuting concurrent update here.
- **`Box<dyn AsyncPort>` via `async-trait`/`dynosaur`; `egui_inbox`; `poll-promise`** — not needed: the runner is generic over one bundle, `wake` is one line, `poll-promise` is unmaintained.
